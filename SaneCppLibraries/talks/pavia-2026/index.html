Caller-owned storage in Async

Requests, buffers and callback state must remain stable until completion.

Read request · setup and error cleanup omitted
AsyncFileRead read;
char buffer[4096];
read.buffer = buffer; // Span<char>: address + extent
read.callback = [&](auto& result) // AsyncFileRead::Result
{
    Span<char> bytes;
    if (result.get(bytes))
        received = bytes.sizeInBytes() == 4;
};
SC_TRY(read.start(loop));
SC_TRY(loop.run());

read is a caller-owned request.

buffer converts to Span<char>. Its size stays part of the contract.

bytes views the completed portion.

loop.run() dispatches the callback while this scope stays alive.

Sane C++ Libraries / Lifetimes18 / 34

Grouping the lifetime of a compile job

SC-build-inspired · one job = one owner
struct Slot
{
    // One compile job owns this whole group.
    AsyncProcessExit exited;
    AsyncFileRead stdoutRead, stderrRead;
    PipeDescriptor stdoutPipe, stderrPipe;
    SmallVector<char, 4096> stdoutBuffer, stderrBuffer;
    bool processFinished = false;
    bool stdoutFinished = false, stderrFinished = false;
    // Reuse the group only after its LAST completion.
    bool reusable() const
    { return processFinished
          && stdoutFinished && stderrFinished; }
};

FIRST: start monitoring a compile job.

Keep its monitor, reads, pipes and buffers together.

LAST: process exit + both streams finished.

Only then can the whole slot serve another job.

Completion of one request does not end the group’s lifetime.

AsyncExecution: sender composition

A prototype built with Codex at C++ Day 2026 · 17 October.

Experimental owning facade · ex = SC::AsyncExecutionProtocol
AsyncExecution app;
SC_TRY(app.create(2));

auto sendEncoded = [&](StringSpan file, uint16_t port)
{
    return app.readFile(file)
        | ex::continues_on(app.getPoolScheduler())
        | ex::then(base64Encode)
        | ex::let_value([&, port](auto& message) noexcept {
              return app.sendTCP("127.0.0.1", port, move(message));
          });
};

SC_TRY(app.run(ex::when_all(
    sendEncoded("first.txt", 19092),
    sendEncoded("second.txt", 19093))));
